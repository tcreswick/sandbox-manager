# Demo recording

This directory holds the assets used to produce the animated demo GIF
referenced from the top-level [`README.md`](../README.md):

| File              | Purpose                                                       |
|-------------------|---------------------------------------------------------------|
| `demo.tape`       | [vhs](https://github.com/charmbracelet/vhs) script — declarative recipe of the demo session |
| `record-demo.sh`  | Wrapper that checks prereqs, pre-pulls the image, records, and cleans up |
| `demo.gif`        | The rendered animation (regenerated by the wrapper)           |

## Why is this not automated in CI?

Rootless Podman needs a real user namespace, working `newuidmap` /
`newgidmap`, and `/etc/subuid` + `/etc/subgid` entries for the running
user. GitHub-hosted runners and most container-based dev environments
either don't have those set up or are themselves nested inside a user
namespace (which makes nested rootless containers fail). The recording
therefore has to happen on a real Linux host that you control. The
tape file is checked in so anyone can re-render the GIF deterministically.

## Prerequisites on the recording host

A glibc-based Linux desktop / server with:

- **Rootless Podman** ≥ 4.0, working. Verify with:
  ```bash
  podman info >/dev/null && echo OK
  podman run --rm docker.io/library/debian:trixie cat /etc/os-release
  ```
  If the second command fails with anything about `newuidmap` or
  `subuid`/`subgid`, fix that first (see the
  [rootless podman setup notes](https://github.com/containers/podman/blob/main/docs/tutorials/rootless_tutorial.md)).
  As a quick sanity check:
  ```bash
  grep "^$USER:" /etc/subuid /etc/subgid    # should print two lines
  ```
- **vhs** — the recorder. Install one of:
  ```bash
  # Go install
  go install github.com/charmbracelet/vhs@latest

  # or a release binary (Linux x86_64)
  curl -L https://github.com/charmbracelet/vhs/releases/latest/download/vhs_Linux_x86_64.tar.gz \
    | sudo tar -C /usr/local/bin -xz vhs
  ```
- **ffmpeg** and **ttyd** — vhs runtime dependencies:
  ```bash
  sudo apt install ffmpeg ttyd        # Debian/Ubuntu
  sudo dnf install ffmpeg ttyd        # Fedora
  ```
- **sandbox** — this repo's binary, on `$PATH`:
  ```bash
  (cd sandbox && cargo install --path . --locked)
  command -v sandbox && sandbox --version
  ```

## Recording

From the repo root:

```bash
./docs/record-demo.sh
```

The wrapper will:

1. Verify every prereq above and abort with a clear error if anything is
   missing or rootless podman isn't usable.
2. Pre-pull `debian:trixie` so the recording doesn't capture the (slow,
   visually boring) image download.
3. Remove any pre-existing sandbox called `demo` so the recording
   always starts from a clean slate.
4. Drive `vhs docs/demo.tape`, which:
   - opens a 1200×720 terminal at font-size 14 with the "Catppuccin
     Mocha" theme,
   - sets a minimal `$ ` prompt so the recording is portable across
     hosts (your real `PS1` doesn't leak into the GIF),
   - types and runs:
     ```
     sandbox create debian:trixie demo
     sandbox exec demo cat /etc/os-release
     sandbox list
     sandbox rm --purge demo
     ```
   - uses `Wait+Screen /pattern/` directives to hold each frame until
     the relevant output appears, so the timing is content-driven
     rather than wall-clock-driven (resilient to fast/slow machines).
5. Write the result to `docs/demo.gif`.
6. Defence-in-depth cleanup of the `demo` sandbox at exit, even on
   failure.

Expected wall-clock time on a typical machine with the image already
pulled: 30–90 seconds, dominated by the in-container `apt` work the
Debian fix-up script performs.

## Iterating

The tape file is deterministic given a fixed `sandbox` version and a
warm Podman image cache. Tweak `docs/demo.tape` (theme, font size,
commands shown, sleeps) and re-run `./docs/record-demo.sh` — each run
overwrites `docs/demo.gif` in place.

Common tweaks:

| Want to…                                  | Change in `demo.tape`                                                 |
|-------------------------------------------|-----------------------------------------------------------------------|
| Make the GIF smaller                      | Reduce `Width` / `Height`, or trim commands shown                     |
| Make typing faster / slower               | `Set TypingSpeed` (e.g. `30ms` faster, `80ms` slower)                 |
| Use a different theme                     | `Set Theme "<name>"` — `vhs themes` lists what's available            |
| Demo a different distro                   | Swap the image in the `Type` line and update the `Wait+Screen` regex if the success banner differs |
| Show a longer interactive session         | Add more `Type "…"  →  Enter  →  Wait+Screen /…/` blocks              |

## Committing the result

Once `docs/demo.gif` looks right:

```bash
git add docs/demo.gif
git commit -m "docs: refresh demo GIF"
git push
```

The top-level `README.md` already references `docs/demo.gif`, so GitHub
will start rendering the new version automatically.

## Troubleshooting

- **`vhs: command not found`** — install vhs (see prereqs above).
- **`ffmpeg: command not found`** or **`ttyd: command not found`** —
  install them; vhs invokes them under the hood.
- **`podman info` fails / `newuidmap: Permission denied`** — your user
  doesn't have a usable rootless Podman setup, or you're inside a nested
  user namespace. The recording cannot proceed in that environment.
- **GIF ends mid-output** — the `Wait+Screen /…/` regex didn't match.
  Run the commands manually, copy a unique substring of the output you
  want to wait for, and update the tape file.
- **Prompt looks weird** — the tape forces `PS1='$ '` in a hidden setup
  block; if you've added shell hooks (e.g. starship, oh-my-zsh) that
  fight that, run the wrapper from a plain `bash` (not your login
  shell) or extend the hidden setup block to disable them.
